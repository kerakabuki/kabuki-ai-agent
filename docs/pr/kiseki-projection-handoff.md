## 1. これは何か

令和8年9月26日の気良歌舞伎『曽根崎心中』公演で、**三幕目（第三場「天神の森」）の直前に暗転で流す投影映像**。

- 1920×1080 / 30fps / mp4（H.264 + AAC）
- **プロジェクタ2台で左右に分けて投影する。左960px＝黒地にテロップ／右960px＝写真**
- 頭と尻は黒。オペレータの操作は **GO 一回だけ**
- 第三幕が短くなるので映像は長めでよい（**現状 約5分46秒**＝OP 18.6秒＋本編 326.9秒）
- 設計原則: **投影が止まっても芝居が成立する**（映像は芝居の前置きであって、芝居の一部ではない）

## 3. 走らせ方

```bash
# カット一覧を見る（写真の差し替え箇所を特定するとき）
node scripts/video/kiseki_build.mjs x --list

# オープニングだけ作り直す（約2分）
node scripts/video/kiseki_open.mjs "D:/気良歌舞伎/台本/曽根崎心中/output/軌跡/OP_v2.mp4"

# 本編＋OP を通しで作る（約25分）
node scripts/video/kiseki_build.mjs "D:/気良歌舞伎/台本/曽根崎心中/output/軌跡/気良歌舞伎の軌跡_v4.mp4" --op="D:/気良歌舞伎/台本/曽根崎心中/output/軌跡/OP_v1.mp4"

# 一部のカットだけ作り直す（--keep と併用。カットを増減したら番号がずれるので通しで作り直す）
node scripts/video/kiseki_build.mjs "...v4.mp4" --op="...OP_v1.mp4" --keep --only=33,59
```

- `--no-audio` で無音のまま出す（音の検品と切り分け用）
- `node --check` が唯一の検証手段。テストもリンタも無い
- ビルドは**リポジトリルートから**実行する

## 7. つまずいた点（同じ罠を踏まないために）

- **sharp は1つのパイプラインで `resize` を2回呼ぶと後の指定に上書きされる** → `extract` の範囲が画像外になり `extract_area: bad extract area` で落ちる。`resize` は1回だけにする
- **`sharp().metadata()` の幅・高さは `rotate()` する前の値**。EXIF回転（orientation ≥ 5）の写真では縦横が入れ替わるので、切り出し計算の前に自分で入れ替える
- **`zoompan` は切り出し位置を整数ピクセルに丸めるので毎フレーム揺れる**（実測 0.22px）。`perspective=x0..y3:interpolation=cubic:eval=frame` で四隅を小数指定すると揺れが消える（同 0.018px）。既にそうしてある
- **`xfade` の入力を70本つなぐと重い** → 12本ずつグループにして畳んでいる
- **365投稿候補のCSVを画質スコアで並べると、幟のアップや祭りの行列が上位に来る**。演目の写真を選ぶときは**必ず `元ファイル` 列で元フォルダを確認**し、`高雄` を含むものを外す
- **2011年の `演目_封印切` `演目_安達ヶ原三段目` フォルダには屋外の祭礼写真が混ざっている**。自動スコアでは屋外のほうが高く出るので目で見て選ぶ
- **`--list` はビルド中に走らせても安全にしてある**（作業フォルダを消さない）。以前ここで進行中のビルドを壊した。`--keep` なしの通常ビルドは `work/body` を消してから始めるので、**2つのビルドを同時に走らせてはいけない**
- Git Bash のヒアドキュメントはバックスラッシュを食う。JS/Pythonを書き出すときは Write ツールを使うか、`chr(92)` で回避する
- `curl` は PowerShell のエイリアスで `-s` を付けるとハングする。`curl.exe` を使う
