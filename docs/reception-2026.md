# 令和八年 気良歌舞伎公演 ご来場・ご祝儀受付

本番用URL：https://kabukiplus.com/kerakabuki/reception/2026

担当者URL：https://kabukiplus.com/kerakabuki/reception/2026/admin

## 当日の使い方

来場者はQRからログインなしで記帳する。紙の芳名帳とどちらか一方を使用する。入力操作を家族が代わる場合も、記帳する本人の名前と案内希望を入力する。

氏名、任意のふりがな、公演案内の希望（郵送・メール・不要）を入力する。郵送の場合だけ住所、メールの場合だけメールアドレスを保存する。郵便番号による町域補完とブラウザーのautocompleteを利用できる。

ご祝儀は「ご祝儀をお持ちの方のみお選びください」の任意チェックで申告する。「ご自身の名義でお持ちのご祝儀」「代理でお持ちのご祝儀」は両方選択できる。該当しない場合は選択せずに記帳でき、確認画面にも「祝儀なし」と表示しない。家族・団体名義は本人分の祝儀袋名義欄で指定できる。

代理持参は「代理でお持ちのご祝儀」にチェックし、祝儀袋ごとに名義人を追加する（1回10件まで）。名義人の住所や案内希望が分からなければ「未確認・わからない」で登録できる。本人の案内希望・利用目的を確認した場合のみ名義人への郵送・メールを登録する。持参者の住所を名義人へコピーしない。

持参者・本人分の祝儀と、代理の各祝儀袋に別々の受付番号を発行する。受付係は画面の番号と祝儀袋名義を照合する。来場者の申告だけで「受領済み」にはならない。観劇せず持参しただけの場合は「ご祝儀のお届けのみ」を選択する。代理名義人とお届けのみの方は観劇の記帳数に加えない。件数は記帳件数であり、同行人数の集計ではない。

登録完了後に観劇記念PNGと任意のYouTubeチャンネル案内を表示する。チャンネル登録、案内希望、祝儀の有無を特典の条件にしない。受付完了画面は祝儀の受領証ではない。

## 担当者

既存のKABUKI PLUS+にログインし、担当者URLを開く。既存の `kera` 管理者または `master` 権限が必要。一般メンバーや他団体管理者には一覧・CSV・更新を許可しない。

紙の転記、氏名・連絡先の訂正、各袋の受領確認、金額（中身未確認なら空欄）、メモを扱える。代理の案内先を訂正する際も本人の希望確認が必要。郵送・メールCSVには祝儀金額・メモを含めず、確認済みの希望者だけを出力する。案内メールの送信機能は含まない。

## 保存・アクセス制限

専用D1 `kerakabuki-reception` を `RECEPTION_DB` として使用する。既存のSNS用DBは使用しない。migrationは `migrations/reception/0001_reception.sql` と `0002_proxy.sql`。

`reception_entries` に来場者・持参者と代理の名義人を別レコードで保存し、`carrier_entry_number` で紐付ける。親と代理の全レコードをD1のbatchで一括保存する。UUIDと正規化した入力のハッシュにより同時再送でも二重登録を防ぐ。担当者の更新はrevisionによる競合検出と `reception_audit` の履歴保存を一括で行う。

画面・APIはno-store、noindex、フレーム埋込禁止。既存Service Workerのキャッシュから受付ページを除外する。JSON更新は同一Originのみ、入力はサーバーでも検証し64KBまで。個人情報・例外本文はログに出さない。CSVの数式注入を無効化し、郵便番号をハイフン付きで出力する。送信制限は1IPあたり120回/60秒（会場Wi-Fiでの共用を考慮した補助的制限）。

住所補完はzipcloudへ郵便番号だけを送る。氏名・番地・メールは送らない。検索に失敗しても手入力可能。

## 開発・検証

Node.js 22以降。`kabuki-post-365` の依存をインストール済みの場合：

```powershell
node scripts/reception-test.mjs
node scripts/reception-preview.mjs
```

依存が別の場所にある場合は `RECEPTION_DEPS` にそのpackage.jsonの絶対パスを指定する。テストは一時D1・KVを使い、59項目を検証する。プレビューは127.0.0.1:8789のみで待受ける。`/preview-admin` はローカルNodeプロキシだけの架空担当者ログインで、本番Workerには存在しない。ローカルDB・KV・test-results.jsonを本番へ取り込まない。

## 公開・運用

受付追加前にGitHub main `d61277b` をビルドしたコードと公開中のWorkerが一致することを確認した。既存の案内動画・ポストカード・解説ページを保持する。カスタムドメイン、KV、R2、AI、秘密値、cronは既存設定を利用する。

新規DBには先に2つのmigrationを適用する。mainへのpushで既存GitHub Actionsが構文検証後にデプロイする。公開後は記帳ページ・拒否されるべき一覧/CSV・住所検索・Service Workerを確認する。テスト登録を行う場合は架空データに限定し、そのrequest_idで特定できるレコードだけを後片付けする。

当日の受付開始前に会場のiPhone/AndroidでQR読取り、登録、画像保存、担当者の実アカウントを確認する。公演後の受付終了と保存期間は運営方針に従う。通信できない場合は紙の芳名帳で受け付け、担当者が後から転記する。
