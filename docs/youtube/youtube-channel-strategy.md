# 気良歌舞伎チャンネル PR戦略（案）

> 2026-08-02 作成。令和8年9月26日「曽根崎心中」公演までを射程に、
> チャンネル本体を伸ばすための出し方をまとめる。

---

## 目的の整理

このドキュメントが扱うのは **チャンネル登録者を増やすこと**。
公演のチケットを売ることとは重なるが同じではない。混ぜると打ち手がぼやけるので分けて考える。

- **チャンネルを伸ばす** … 時期を問わない。気良歌舞伎そのものの面白さで新規を拾う。
- **9/26公演に集客する** … 期限つき。日付と場所を届ける。

以下は前者を主、後者を従として組み立てている。

---

## 1. プラットフォーム判断

**結論: YouTube Shorts を主軸、同じ縦型1本を Instagram リールに二次配信。TikTok は当面やらない。**

| | 判断 | 理由 |
|---|---|---|
| **YouTube Shorts** | ◎ 主軸 | 視聴者が同一プラットフォーム内にいる。バズったShortsのアイコンをタップした先がそのままチャンネルで、長尺の「超訳！歌舞伎ナビ」が並ぶ。**チャンネル登録までの摩擦がゼロ**。他所からの誘導はここで大半が落ちる。 |
| **Instagram リール** | ○ 併用 | すでに kabuki-post-365 で運用中。既存フォロワーと地元・既存ファン層が乗っている。縦型は同じファイルをそのまま出せるので追加コストが実質ゼロ。ただし新規開拓力はShortsに劣る。 |
| **TikTok** | × 見送り | 新規リーチ力は最強だが、(1) 外部リンクが弱くYouTubeへの導線がほぼ機能しない (2) 主要ユーザー層が9/26の客席に来る層とも長尺解説を観る層ともズレる (3) 3プラットフォーム目の運用が単純に手間。**「伸びた実感」と「チャンネルが伸びる」が一致しにくい**。 |

TikTokをやるとしても、Shortsで当たったネタを事後的に転載する検証枠に留める。先行投資はしない。

**縦型9:16を1本作って2箇所に出す。これ以上分岐させない。**

## 2. 素材の使い分け — 実写とイラスト

制作を通じて出た一番大きな判断。

### 実写が強い

冷たい視聴者に対する最強のフックは **「田舎の素人が、本気で歌舞伎をやっている」** という事実そのもの。
イラストはこのフックを自分で消してしまう。浮世絵調の絵が出た瞬間、視聴者の頭には「歌舞伎の解説コンテンツ」という枠が立つ。そこは競合が大勢いる場所で、しかも気良歌舞伎である必然性がない。

実写だと枠が変わる。隈取りの顔が出て「これ、岐阜の山あいの村の人たちです」と乗ると、情報の意外性で止まる。
**イラストは「歌舞伎の話」、実写は「この村の話」。後者にしか固有性がない。**

### それでもイラストに役割はある

『曽根崎心中』はまだ上演していないので実写が存在しない。天満屋も天神の森も撮れる映像がない。

| 素材 | 使いどころ |
|---|---|
| **実写** | 「誰がやっているか」を見せる部分。フック、稽古、化粧、客席、過去公演のハイライト。 |
| **イラスト** | まだ存在しないものを見せる部分。曽根崎の場面、物語の説明。 |

### 発見: 本編アーカイブが未活用

`D:\気良歌舞伎\ビデオ\` に平成17年〜令和7年の公演映像が蓄積されているが、**一度もショート化されていない**。
令和7年 五代目座長襲名披露公演（3幕・計86分）を確認したところ、1080pで白塗り・隈取りの顔が画面中央にアップで抜かれたカットが多く、9:16センタークロップにそのまま収まる。**公演告知が終わっても使い続けられる資産**であり、ここが当面の主力になる。

## 5. 英語版の扱い

ナレーション音声がなく字幕だけの構成なので、**翻訳して差し替えるだけで作れる**（TTS録り直し不要）。
作成コストが実質ゼロの回だけ英語版も一緒に出し、反応を見てから本気で作り込むか決める。

翻訳方針:
- 直訳しない。「田舎の素人が」は身内の自虐として機能するが、英語に直訳すると見下しに読める。
  **「素人／本気」の対比構造だけ残して言い回しを作り直す。**
- 演目名は英訳せずローマ字表記（`Kotobuki Soga Taimen` 等）。一行字幕で説明する余地がないため、
  タイトルとして提示するに留める。
- フォントも分ける（日本語 Yu Mincho / 英語 Georgia）。

## 6. 投稿頻度と更新リズム

**週1〜2本を目安に様子を見る。最初から量産しない。**

Shortsを量産してもYouTubeのアルゴリズム上の直接的なペナルティは基本的にない
（ShortsフィードとLong-formのおすすめは別系統）。ただし注意点が2つある。

- **Shorts経由の登録者は長尺をあまり見ない傾向**がある。登録者数は増えるが総視聴時間が伴わない状態になりやすい。
- 通知・ホーム画面ではShortsと長尺が混ざるため、頻度が高すぎると
  「歌舞伎の本気解説チャンネル」という認識が薄まりうる。

> ※ 上記は一般的なプラットフォーム挙動であり、このチャンネルで実測した数値ではない。

### 制作の波と投稿の波を分ける

一番現実的な運用は **まとめて作って、ストックから一定間隔で出す**。

素材集めと編集は気分と時間の都合で波が出る。今日のように「本編映像を漁ってカットを決める」作業は
半日かかるが、一度やれば数本分のカットが手に入る。それを1本ずつ小出しにする。

**制作が止まっても投稿は止まらない**状態を作るのが目的。逆に「今週出す分を今週作る」方式にすると、
忙しい週に途切れ、途切れたまま戻らなくなる。これが個人運営のチャンネルが死ぬ一番多いパターン。

### 途切れるより、間隔が空く方がマシ

週1が守れないなら隔週でいい。**不定期でも「出続けている」ことの方が、頻度そのものより効く。**
無理に埋めるために質の低い1本を出すと、それを見た新規がチャンネルを判断してしまう。

公演前後で密度が変わるのは自然。実質「8月は①のみ、9月に②が1〜2本、公演後にまとめて数本」でよい。

## 7. 自動化の功罪

このリポジトリはすでに自動化を多用している（kabuki-post-365の日次SNS投稿、今回の動画ビルド）。
経験上わかっていることを整理しておく。

### 功 — 何が良くなったか

- **「もう1本」が安くなる。** 今日、実写PVの英語版は字幕を差し替えるだけで作れた。
  手作業なら「英語版も作るか…」で終わっていた話が、実際に作られた。
  **選択肢が増えるのではなく、実行される確率が上がる**のが本質的な効き目。
- **比較検証ができる。** `cropX` がパラメータ化されているから「0.35と0.68を試して見比べる」が成立する。
  手作業だとやり直しが億劫で、最初の妥協案がそのまま完成品になる。
- **継続の心理的コストが下がる。** 1本作るのに気合いが要らなくなること自体が、更新が途切れない最大の担保。

### 罪 — 何が壊れたか（実測）

| 事例 | 何が起きたか |
|---|---|
| **Facebook 日次API投稿** | 自動投稿は成功していたが、**フォロワーへの配信が実質0%**だった。「出している」状態は作れるが「届いている」とは限らない。→ API投稿を停止し、大型告知のみ人力＋シェアに変更 |
| **kabuki-post-365 の画像紐づけ** | AIが誤ったキャラクター画像を本文に紐づけ、本番に出かけた。**検品ゲート（verified）をコードで作る羽目になった** |
| **今日の実写PV** | スクリプトは30秒で組んだが、初版は寿曽我対面が見得の一瞬を外し、封印切はカメラのパン中でぼかしが汚かった。**フレームを目視するまで気づけなかった** |

共通しているのは、**自動化は「生成の速さ」を上げるが「判断の質」は上げない**ということ。
むしろ生成が速くなった分、判断が追いつかないまま公開まで進んでしまうリスクが増える。
**間違いも自動で拡散する。**

### このチャンネル固有の相性問題

価値の源泉が「田舎の素人が本気でやっている」という人間くささにある以上、
**量産された感じが出た瞬間にその価値が薄まる**。皮肉だが、自動化が最も効きにくいジャンルにいる。

視聴者は「毎日更新されているな」ではなく「この人たち本気だな」で登録する。
頻度は手段であって目的ではない。

### 引くべき線

| 自動化してよい | 自動化してはいけない |
|---|---|
| ffmpegでの組み立て・書き出し | **どのカットを使うか** |
| フォーマット変換・縦横変換 | **いつ出すか** |
| 多言語の字幕差し替え | **文言（特にキャッチコピー）** |
| サムネイル候補の切り出し | **公開ボタンを押すこと** |
| 投稿の予約セット | 出来上がったものの良し悪しの判定 |

**原則: 生成は自動、公開は手動。**
そして公開前に必ず現物を見る。今日のPVも、フレームを抜いて目視したから2箇所直せた。
このチェックを省いた瞬間に、上の表の失敗が繰り返される。

### 技術的な知見

- 16:9素材を9:16に流用するとき、ぼかし埋め（blurpad）は画面の2/3が死んで弱い。
  **被写体が中央にある絵は全画面クロップ（cover）、端に寄っている絵だけ blurpad**。
  カットごとに `cropX` で注視点を指定する。
- 実写は「その1秒がどんな絵か」を毎回確認しないと事故る。見得のピークを外したり、
  カメラのパン中でぼかしが汚くなったりする。候補区間を1秒刻みで再サンプリングしてから確定すること。
