演目ID「$ARGUMENTS」のnote記事を生成してください。

## 手順

1. 演目カタログから該当演目のエントリを探す：
   ```
   npx wrangler r2 object get keranosuke-enmoku-data/catalog.json --remote --pipe
   ```
2. 演目の詳細JSONをR2から読む：
   ```
   npx wrangler r2 object get keranosuke-enmoku-data/{演目ID}.json --remote --pipe
   ```
3. 公演情報を確認する（**記事本文には書かない**）：
   - `https://kabukiplus.com/api/performances` から現在の公演一覧を取得し、演目名で検索する
   - API に演目レベルのデータがない場合は、WebFetch で `https://www.kabuki-bito.jp/theaters/` 等を確認する
   - 上演中・近日上演の公演が見つかったら、劇場名・日程は**完了報告でユーザーに伝えるだけ**にする（SNS告知の材料）。記事は恒久コンテンツなので、日付つきの告知を本文に入れると古い情報として残る（2026-03のコラムに南座公演の告知が残り、手で消した実害あり）
4. 以下のルールに従って記事を生成し、`note-articles/{演目ID}.md` に保存する
5. 保存したファイルに下の「公開前チェック」をかけ、引っかかった箇所を直す
6. frontmatter（`---`で囲まれた部分）と画像プロンプト（`<!-- 画像生成プロンプト ... -->`）を除いた**記事本文だけ**をクリップボードにコピーする。Windows環境ではUTF-8文字化け防止のため以下のコマンドを使うこと：
   ```
   sed -n '/^# /,/^<!-- 画像生成/{ /^<!-- 画像生成/d; p; }' note-articles/{演目ID}.md | powershell.exe -NoProfile -Command "[Console]::InputEncoding=[System.Text.Encoding]::UTF8; Set-Clipboard -Value (([System.IO.StreamReader]::new([Console]::OpenStandardInput(), [System.Text.Encoding]::UTF8)).ReadToEnd())"
   ```
7. 画像生成プロンプト（記事末尾の英語版と、下の「Gemini用の日本語画像プロンプト」）はターミナルに表示する。**クリップボードには入れない**（記事本文を上書きしてしまう）
8. 「クリップボードにコピーしました。noteに貼り付けてください」と伝える。手順3で公演が見つかっていれば、ここで一緒に伝える

## 記事ルール

### 対象読者
歌舞伎初心者。映画・ドラマきっかけで興味を持った人。初観劇の人。

### 構成（必須）

#### 冒頭メタ情報
```
---
title: 記事タイトル
enmoku_id: 演目ID
target_url: https://kabukiplus.com/kabuki/navi/enmoku/{演目ID}
created: {今日の日付 YYYY-MM-DD}
status: draft
---
```
frontmatter の直後、本文の1行目は `# {記事タイトル}` にする（手順6のコピーはこの行から始まるので、無いとクリップボードが空になる）。

#### 1. 導入（リード文）
- 今なぜこの演目が注目か（映画・ドラマ・季節など、時間が経っても古びない切り口で。公演の日程は書かない）
- 「初めてでも大丈夫」という安心感

#### 2. ざっくりあらすじ
- ネタバレしすぎない程度に3〜5段落
- 登場人物は主要3人程度に絞る
- 最後に「つまりこういう話」と一言まとめ

#### 3. ここが面白い！（見どころ）
- 初心者が「おっ」と思えるポイント2〜3個
- 有名なセリフや場面の紹介
- 「ここで拍手が起きます」等の体験描写

#### 4. 観に行くなら（観劇Tips）
- イヤホンガイドの推奨
- おすすめの席
- 予習不要であることの安心感
- 特定の公演の劇場名・日程は書かない（手順3のとおり）

#### 5. 末尾誘導（必須・以下の形式で）
```
---

📖 **この演目をもっと詳しく**
登場人物の詳しい解説やあらすじの全文は「KABUKI PLUS+」で読めます。
👉 https://kabukiplus.com/kabuki/navi/enmoku/{演目ID}

📓 **観劇したら記録を残そう**
「KABUKI RECO」で観劇ログをつけると、あなただけの歌舞伎アルバムが完成します。
👉 https://kabukiplus.com/kabuki/reco

---
```

### 文体
- ですます調。親しみやすく、でも軽すぎない
- 専門用語には（）で読みと簡単な説明を添える
- 絵文字は見出しのみ。本文中は使わない
- 文字数：2000〜3000字

### SEOタイトル
「【初心者向け】{演目名}のあらすじ・見どころをやさしく解説」

## タイトル画像プロンプト

記事の一番最後（ハッシュタグの後）に、以下の形式でタイトル画像生成用プロンプトを出力する：

```
<!-- 画像生成プロンプト
Style: 和風・浮世絵風イラスト、テキストなし
Size: 1200x630
Prompt: {演目の象徴的モチーフを含む英語プロンプト}
-->
```

色調は和の配色（金・朱・藍・墨など）。演目の象徴的なモチーフ（桜、刀、月、雪など）を含める。

## Gemini用の日本語画像プロンプト

記事保存後、Geminiチャット用の日本語画像生成プロンプトをターミナルに表示する（クリップボードは記事本文のまま）。フォーマット：

```
以下の条件で画像を1枚生成してください。

用途：note記事のタイトル画像（{演目名}）
サイズ：横長（16:9）
スタイル：浮世絵風のイラスト調
モチーフ：{演目の象徴的なモチーフ}
色調：{和の配色}
雰囲気：{演目に合った雰囲気}
テキスト：なし（文字を入れないでください）
人物：なし
```

## noteハッシュタグ

記事末尾の誘導リンクの後、画像生成プロンプトより前に、noteのハッシュタグを出力する（手順6の sed は画像生成プロンプトの手前までをコピーするので、後ろに置くとハッシュタグが抜ける）。以下の固定タグ＋演目固有タグを組み合わせる：

### 固定タグ（毎回必ず含める）
```
#歌舞伎 #kabuki #歌舞伎初心者 #伝統芸能 #日本文化 #観劇 #舞台 #KABUKIPLUS
```

### 演目固有タグ（演目に応じて追加）
- 演目名（例: `#曽根崎心中`）
- 作者名（例: `#近松門左衛門`）
- ジャンル（世話物なら `#世話物`、時代物なら `#時代物`）
- 関連キーワード（映画・ドラマ関連があれば追加。例: `#国宝` `#吉田修一`）
- 地歌舞伎関連の演目なら `#地歌舞伎`

## 公開前チェック（手順5）

note は Markdown を一部しか解釈しない。書き方の立場も含めて、保存後に必ず確認する：

- **表を使わない** — `| A | B |` は生のまま表示される。表にしたい内容は「**見出し** ―― 説明」の行の連なりにする
- **太字の閉じ `**` の直前が約物（。」』など）で、直後が普通の文字なら壊れる** — 閉じ `**` の直後に全角空白を一つ入れる
- **「盗」「咎」「無断」「けなす」「笑う」「資格」を全文検索する** — 芝居は目の前の客を喜ばせるエンタメとして書く。「高尚な芸術」の物差しを持ち込んだ弁護・対比の構え（「盗用ではない」「笑う資格はない」など）になっていたら、仕組みだけを述べる形に直す
- **日付つきの公演告知が本文に無いこと**（手順3）
